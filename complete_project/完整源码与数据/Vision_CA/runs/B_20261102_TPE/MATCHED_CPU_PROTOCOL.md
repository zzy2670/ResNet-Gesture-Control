# A/B 六模型同输入 CPU 速度补充基准

本协议在执行前固定。原有 A/B `cpu_latency.json`、分类速度结果、权重和阈值全部保留。补测只回答相同输入与运行条件下六模型的速度，不重算准确率，不选择权重、阈值或最快的一轮，不把验证样本速度当成跨协议泛化准确率。

输入取 A 的固定验证集：完整照片按 `image_id` 排序的前100张；纯分类输入独立取 A 的 `crops_val.json` 按 `(image_id, hand_index)` 排序的前100张 GT 手图。六模型使用相同的完整照片和相同的分类输入。保存样本ID、源照片SHA256、裁图SHA256和预处理张量SHA256；读取和哈希不进入计时。GT手图使用既有 JPEG 裁图及与原 CropDataset 一致的 RGB、ToTensor、ImageNet Normalize，224×224。

固定 CPU、float32、8个 PyTorch 算子线程，一张输入照片或一个纯分类张量为一次调用。纯分类预处理在计时前完成，只计分类器前向。整图直接调用原 `train_A.whole_photo_predictions`，`rows=[row], batch_size=1`，包含 PIL 打开解码、检测、裁图、分类、概率和规则处理。整图内多只手仍按原接口一次成批分类，不能误称为内部每只手都 batch1。每组模型保留自己已冻结的检测和分类阈值及真实检测框数量，不人为统一工作量。每照片每轮保存固定检测阈值后的手框数及分类接受数；不保存或评价新的准确率。

六组分类器显式构建对应 ResNet18/34/50，严格加载原 checkpoint。检测器使用 `deployment_src.gesture_predict.build_hand_detector` 离线构建训练使用的 full-tail SSD320 后严格加载原 checkpoint，避免预训练缓存或网络依赖；使用的是原整图函数，不是包内额外包含路径解析、输出解释文本的 `predict_details` 计时。此工厂只影响计时前构造，计时内的原函数和原裁图规则不变。脚本保存相关源代码哈希。模型加载不计入速度。

全部六模型提前加载且常驻内存。每个scope先依次为各模型预热20次，然后计时3轮，每轮每模型固定顺序遍历全部100个输入，保留全部300个原始毫秒时间。模型基础顺序为 A18、B18、A34、B34、A50、B50；第2轮逆序；第3轮基础顺序循环左移3位。先执行纯分类scope，再执行整图scope。该顺序降低持续漂移影响，但3轮无法完全平衡所有位置；模型、环境和时间波动仍可能影响速度，不能只从一组反常结果推出网络更深反而更快。

记录 mean、p50、p95、样本标准差(ddof=1)与逐轮均值，同时保存原始时间、真实工作量、权重/校准/代码身份、时间、PyTorch/TorchVision版本、CPU/线程/内存和每计时块前后的系统及本进程CPU计数。其他进程占用率由系统忙碌CPU时间扣除本进程CPU时间估计，仅用于背景负载解释，不据此剔除计时。全部计时包含 Python 调用开销和自然缓存效应。

默认运行只显示本协议，`--help`与默认调用不导入重型库、不执行模型。只有协调者确认无其他重CPU任务后才调用 `python benchmark_AB_matched_cpu.py --run`。结果为 `matched_cpu_benchmark.json`；结果先编码成字节，紧邻独占创建前重新核对六模型双权重/校准、脚本/协议/调用源码、输入索引/标注以及选中原图/裁图的全部SHA，再提交同一份字节；上述核验均在计时外。首次运行创建独占 `matched_cpu_benchmark.attempt.jsonl` 并持续保存完整计时块，异常记录错误和部分证据。已有结果或尝试日志则拒绝覆盖或自动重跑；不得删除失败日志以取得更快结果。
