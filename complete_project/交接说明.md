# ResNet合并与不合并标签任务完整交接说明

ResNet识别分支由我和组员共同负责。现保留不合并实验，并在相同固定A照片划分、B人员划分上另训合并标签的六个分类器，共十二个自带权重的CPU识别程序。方案v12和综合报告v3同时解释两种任务，旧模型、方案v11和报告v2原样保留。组员可先接收复核、主笔ResNet汇报，再与另一识别子组和控制组继续比较及集成。

## 1 项目在做什么

### 模块职责与两类接口

整图识别由三个部分协作完成：SSDLite在完整照片中检测手框，可以给出多个框，也可能漏检或误检；ResNet分别对每个检测框裁出的手部图计算六类分数，也可能分错。多张裁图可以成批计算，但ResNet本身不负责找手或多手汇总。程序再用独立Python规则处理达到分类置信阈值的结果：存在已接受的3就输出3；否则非0指令只有一种时输出该指令，多种指令冲突或没有非0有效指令时输出0。0类手不会抵消另一只手的有效指令。这套流程不能保证照片中的所有手都被找到并正确分类。

整图程序接口与分类器接口应分开理解：GesturePredictor.predict读取完整照片，经过检测、裁图、分类和规则汇总后返回一个0—5整数；predict_details还返回框、各类概率、是否接受和汇总原因。ResNet分类器只读取预处理后的单手图张量并返回六类分数。控制约定中，0表示无新指令，不发起或续期运动，也不作为取消当前运动的停止命令；3才是明确停止。命令有效期和运动响应仍需控制端实际联调。

一张照片的公开输出始终只有一个数字。两只手都通过检测与分类阈值后，1＋1汇总为1，1＋2因动作冲突汇总为0，1＋3因停止优先汇总为3，1＋0仍汇总为1。程序内部保留每只手的框、类别和置信度，predict_details或可选JSON可查看这些明细；GesturePredictor.predict返回一个整数，CLI成功时stdout也只打印这个最终整数，不逐只手返回多个数字。


电脑读入一张完整RGB照片，先找到照片里的手，再裁出手部区域，用训练好的ResNet判断手势，最后把各只手的结果合成为0—5中的一个整数。例如照片中出现V形手势，输出1；控制侧可将1解释为前进。

完整流程是：完整RGB照片 → SSDLite320 MobileNetV3找手 → 按框中心裁出留边正方形并缩放224×224 → ResNet六类分类 → 置信度和多手规则 → 输出整数。检测器回答手在哪里，ResNet回答手势是什么；规则决定这一张照片最后接收哪个动作。

| 数字 | 不合并版 | 合并版 | 控制约定 |
|---|---|---|---|
| 1 | peace、peace_inverted | peace、peace_inverted、two_up、two_up_inverted | 前进 |
| 2 | stop、stop_inverted、palm | 相同 | 后退 |
| 3 | fist | 相同 | 明确停止 |
| 4 | like | 相同 | 左转 |
| 5 | dislike | 相同 | 右转 |
| 0 | 其余raw手势；运行时无有效非0或冲突 | 相同，但不再包括两种two_up | 无新指令 |

0不发起或续期运动，也不是取消当前运动的命令；3才是明确停止。数据集名为stop的张掌标签属于后退2。两种two_up在不合并版为0、合并版为1，必须先选任务再看样例预期。识别器目前只产生数字，控制侧实际执行仍需联调。

存在被接收的握拳时优先输出3；否则，可靠非零手势只表示同一动作就输出该数字，存在不同动作则输出0。闲置手的0不会抵消另一只手的有效命令，例如V形手加闲置手仍输出1。

## 2 数据与训练怎样理解

课程使用HaGRID Sample 30K的384p样本版，共31,833张照片、7,973名人员、38,884个手框。HaGRID全称为HAnd Gesture Recognition Image Dataset；本地课程副本来自cj-mills发布的hagrid-sample-30k-384p。384p指保持宽高比缩小，短边约384像素。一个照片可能有两只手，手框数与照片数不同。

A与B是这同一批照片的两套评价方法。A按照片随机分组，同一个人的不同照片可跨组；B按user_id人员分组，一人的全部照片只在一组。两协议之间可以复用原图，各自内部则保持照片隔离，B还保持人员隔离。

| 协议与子集 | 人员 | 完整照片 | 手框 |
|---|---:|---:|---:|
| A训练 | 6,999 | 25,468 | 31,095 |
| A验证 | 1,876 | 3,185 | 3,872 |
| A测试 | 1,931 | 3,180 | 3,917 |
| B训练 | 6,379 | 25,274 | 30,799 |
| B验证 | 797 | 3,457 | 4,326 |
| B测试 | 797 | 3,102 | 3,759 |

A三组人数存在交叉，不能相加当作独立人员总数。B三组人员、图片编号、精确内容SHA256两两交集都为0，所有原图与原标注保留。B按人数约80/10/10分配，因为每人照片数不同，照片比例约79.40%/10.86%/9.74%。

训练组提供手图与正确六类答案，模型根据预测误差调整参数；验证组选择设置、轮次和阈值；测试组在这些选择固定后评价。ResNet18、34、50是三种网络结构，权重是训练得到的数值。三者都从官方ImageNet V1分类参数开始，B没有继承A已训练的分类器或手检测器。

原不合并六分类器各做24次冻结头TPE、每次18轮，再微调layer4和分类层；A实际18/18/18轮，B18/18/11轮，B50按原patience4自然早停、最佳第7轮。新增合并不再TPE：各协议／架构复用自己旧已选参数，按新标签另训新头18轮，再从官方ImageNet主干与这次新头微调，最多18轮／patience4；不从旧微调分类器继续训练。A和B检测器各自原权重复用、不重训。各模型的接收阈值在自己的验证结果中固定，测试不参与选型。

| 合并模型 | 头轮数 | 头最佳 | 微调完整轮 | 微调最佳 | 阶段 |
|---|---|---|---|---|---|
| A ResNet18 | 18 | 16 | 16 | 12 | layer4＋fc |
| A ResNet34 | 18 | 15 | 18 | 14 | layer4＋fc |

## 5 怎样运行与对接

解压后按所选模型README安装依赖，从总包根目录运行：

```powershell
cd "程序/不合并/A/resnet18"
python predict.py "examples/1.jpg"
python predict.py "你的照片.jpg" --json "result.json"
```

若选择合并，进入`程序/合并/A/resnet18`；也可选择相应B协议或resnet34／resnet50。十二目录各含predict.py、config.json、requirements.txt、weights、examples、samples.json、SHA256SUMS.json和README，使用各自真实权重、阈值与映射。推理小包是已核CPU便携入口；先按README准备兼容依赖，首次安装可联网，预测不下载模型。已核环境见各包README，新机器仍需检查本机依赖。

成功时stdout只有一个0—5整数；照片不存在、损坏、模型缺失等错误写stderr，进程以非0退出，不把异常变成正常0。详细JSON保存每只手的框、检测分数、六类概率、是否接收、整图数字与原因。集成端要同时检查退出码和标准输出。

Python调用使用同一个GesturePredictor实例处理多张图，避免反复加载模型：

```python
from predict import GesturePredictor
predictor = GesturePredictor("config.json", device="cpu", threads=8)
number = predictor.predict("你的照片.jpg")
details = predictor.predict_details("你的照片.jpg")
```

Python方法成功返回整数或详细字典；读图等异常向调用方抛出。控制组需明确调用或消息方式、数据类型、发布频率、命令有效期、0与3及异常／超时处理，再用真实照片或摄像头帧驱动仿真并保留记录。
